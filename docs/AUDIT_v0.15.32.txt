Data safety
- renderer는 current target PUUID와 local account PUUID가 다르면 snapshot annotation 및 calibration을 차단.
- main collector도 현재 core account와 다른 supplied PUUID를 거부.
- Riot Grade가 저장된 record가 없는 gameId는 ROLE snapshot을 새 Grade처럼 생성하지 않음.
- Queue 450 / 2400 외 snapshot 거부.
- calibration history는 현재 queueId와 같은 snapshot만 집계.

Scoring isolation
- roleSnapshot은 검증/분석용 metadata이며 ROLE 계산에 입력하지 않음.
- scoringUse=false / snapshotScoringUse=false 유지.
- Riot Grade를 가산/감산하거나 자동 보정값을 생성하지 않음.
- v0.15.29 Mission/Death Fairness 및 v0.15.25 CC 영향력 결과를 당시 ROLE score snapshot으로만 기록.

Engine version guard
- engineKey = ROLE_FAIRS15_CC25_MISSION29.
- 현재 calibration은 동일 engineKey snapshot만 사용.
- 향후 ROLE 엔진이 크게 변경될 때 새 engineKey로 분리해 과거 기준과 새 기준의 혼합을 막을 수 있음.

30-match limitation fix
- v0.15.31은 현재 aramHistoryState.matches와 저장 Grade를 join했기 때문에 실제 calibration 표본이 Match Lab 최대 30경기 범위에 사실상 묶였음.
- v0.15.32는 현재 보이는 경기에서 ROLE snapshot을 Grade record에 annotation한 뒤, 이후 집계는 userData의 snapshot 전체를 사용.
- 따라서 snapshot이 한 번 저장된 경기는 최근 30경기 밖으로 밀려나도 calibration 표본으로 유지됨.

Known limitations / actual environment not executed
- 실제 Windows Electron + Riot Client 게임 종료에서 Grade 수집이 정상인지 아직 사용자 E2E 필요.
- 기존 v0.15.28~31 Grade 중 현재 30경기 밖으로 이미 밀려난 경기에는 ROLE snapshot이 없으므로 완전 소급 복원 불가.
- 실제 역할 전환 중 calibration panel 위치/레이아웃 육안검사 미실행.
- 장기간 수백 경기 누적 시 실제 userData 파일 I/O 체감 성능은 사용자 환경에서 추가 확인 필요. 최대 600 record라 구조상 작지만 E2E 미검증.
