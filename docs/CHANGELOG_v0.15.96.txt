ARAM Fearless Draft v0.15.96 — RESULTS SYNC HOTFIX

Purpose
- Fix the v0.15.95 IN GAME result dashboard so the just-finished standard ARAM match is actively refreshed from Match Lab / League Client history after game end.

Root cause
- v0.15.95 correctly detected LIVE -> non-LIVE and switched to the Result tab, but the Result renderer only consumed the already-loaded aramHistoryState.
- No post-game loadAramHistory(true) refresh was triggered, so the result screen could stay on sync-wait or show only previously loaded Match Lab data.

Fix
- Reuse the existing Random In-game coach heartbeat; no new setInterval or MutationObserver is introduced.
- On game end, force the result history query to the current League account and standard ARAM queue.
- Call the existing Match Lab history loader and retry with bounded backoff up to 10 attempts while the League Client publishes the completed match.
- Compare the latest history game key with the live game id / pre-finish baseline before accepting it as the just-finished result.
- Block stale previous-match presentation while the post-game refresh is unresolved.
- If all retries fail, show an explicit retry state instead of presenting old data as the new result.
- Reopening the Result tab refreshes Match Lab history; when a just-ended game is still unresolved, the stale-result guard remains active.

Compatibility / safety
- Draft, pick, ban, composition and champion scoring are unchanged.
- Item recommendation scoring is inherited unchanged from v0.15.95.
- v0.15.79 safety-baseline lineage is preserved.
- v0.15.95 result-dashboard audit was made forward-compatible and v0.15.96 has a dedicated result-sync audit included in Full Regression Audit.

Real-session validation
- CI/source auditing can validate wiring, parsing, manifest integrity, bounded retry behavior and regression contracts.
- A real Windows + League post-game transition is still the final environment check for League Client match-history publication timing.
