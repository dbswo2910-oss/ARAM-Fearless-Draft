# ARAM 개발 기준

사용자 승인된 제품 기준. 구현 상태는 최신 GitHub 코드를 확인하며, 코드의 기존 동작이 제품 원칙보다 우선하지 않는다.

- 정확성/오류방지 > 실제 사용자 가치 > 직관성 > 전문성/객관성 > 성능/안정성 > 시각 완성도 > 재미.
- 요약 → 비교 → 원인 → 상세. MATCH LAB → PLAYER → ROLE → CHAMPION → MATCH 구조 유지.
- 문제 발견 → 근거 조사 → 일반 원인 수정 → 테스트 → 회귀검사 → 재검토를 자율 수행. 중간 승인 불필요. 대규모 데이터 모델 교체/핵심 시스템 제거만 사용자 승인.
- 새 기능은 가치·빈도·중복·복잡성·자료·오류·유지보수 검토 후 추가. 단순화도 개선.
- 관측 사실 → 합리적 추론 → 확인 권장. 리플레이 없는 장면 판단 금지.
- 챔피언 Function18 임무/실제 빌드/역할에 따라 평가. 실력과 플레이 성향 분리.
- 표본 기간을 목적별로 구분. 소표본 표시. 외부 분포 없으면 백분위 생성 금지.
- 재미 코멘트는 데이터 조건을 만족할 때만, 전문 분석과 구분.
- 코칭은 1개 핵심 목표와 다음 경기 검증. 생존과 딜 등 상충 지표를 함께 확인.
- Queue 450/2400 및 계정 PUUID 격리. 누락 값은 0이 아님.
- LIVE 시간대 전력은 정상 5:5 기준. 생존 인원/최근 킬 제외. 장비·코어·레벨·핵심 레벨·성장곡선 사용. 불완전한 축은 제외 및 대기 표시.
- Riot Grade는 검증 라벨만 사용(scoringUse:false). 정답으로 단정/ROLE 합산/개인 소표본으로 전체 엔진 자동 보정 금지.
- 관측성은 직접/대리/관측불가로 구분. 관측불가 감점과 임의 챔피언 보너스 금지.
- 희생 데스는 입증된 근거로 원래 감점 일부만 환급. 원래 감점 초과 및 CC/탱킹 중복 가점 금지. 173챔 전수 기준표 먼저 검토.
- 최신 HEAD, manifest, main 런타임 순서를 먼저 확인. 중복 구현·미연결 패치·이전 패치 재주입 금지.
- QA: 문법/부팅/메뉴/숫자 이상/빈 전적/null/소표본/동점/극단값/전체 챔피언/추천 대표 사례/순위 급변/역할/큐/버튼/상세/접기/스크롤/overflow/좁은 화면/updater.
- 배포 순서: 테스트 → 회귀검사 → 버전 → CHANGELOG → AUDIT → 배포 파일 → manifest → GitHub. 실패 상태 정상 릴리스 금지.
- 자동 검증과 Windows/Riot/Live API/DPI 실제 환경 검증을 구분.
- 큰 작업마다 목적·질문·이유·근거·사실·문제·심각도·원인·수정·테스트·위험·다음 항목을 텍스트 기록. 01_CURRENT_STATE_AUDIT.txt, 99_FINAL_REPORT.txt 필수.
- 핵심 검증이 충분하고 의미 있는 추가 문제가 없으면 종료. 환경 차단은 명시하고 미완료를 완료로 표시하지 않음.
- 사용자에게 최종 패치노트 핵심 요약만 전달. 충돌 방지용 분리 브랜치 사용, main 반영 직전 HEAD 재확인.
